# Known divergences from pdfminer.six

Everything the port does differently from pdfminer.six, why, and which inputs it affects. Each
entry has an id that the code marks with `// DIVERGE(<id>)`. Nothing that is not listed here may
differ; a difference found by `tools/difftest.py` that is not in this list is a bug.

| id | What differs | Why | Affected inputs |
|---|---|---|---|
| `bigint` | Python ints are unbounded; the port uses `i64`. Integer tokens beyond i64 become the nearest float, int arithmetic that overflows continues in floats, `int(x)` of a float beyond i64 raises `OverflowError`, `nunpack` of more than 8 bytes keeps the low 63 bits. | Unbounded ints would slow every number for inputs that do not occur in real PDFs. | Malformed files with integers of 19+ digits. |
| `int-truediv` | `a / b` of two ints beyond 2**53 rounds twice. | Same as `bigint`. | Same as `bigint`. |
| `charset-normalizer` | `make_compat_str(bytes)` decodes UTF-8 or falls back to `str(bytes)`; Python guesses the encoding with charset_normalizer. | charset_normalizer is a heuristic with no stable specification. | `HTMLConverter`/`TagExtractor` output for font names or tag properties that are bytes and not UTF-8. |
| `heap-id-ties` | `LTLayoutContainer.group_textboxes` orders pairs of boxes with equal distances by `id(obj1)`, `id(obj2)`. The port uses the objects' creation order as `id` (`LTItem::id`, a serial number). | CPython's `id` is a memory address, so pdfminer.six's own grouping of tied pairs depends on the allocator: it changes between runs of the same file (seen on `kampo.pdf` and `issue-598-cmap-other-fonts.pdf`). Addresses follow creation order most of the time. `tools/gen_testdata/layout.py` makes Python use the same rule (it replaces `id` in `pdfminer.layout`); a Python reference that keeps the real `id` (e.g. `tools/oracle.py`) is not reproducible on these files. | Pages where two pairs of text boxes or groups are exactly as far apart: `LTPage.groups` and the order (and `index`) of the text boxes can differ from a given pdfminer.six run. Among the samples: `nonfree/f1040nr.pdf`, `nonfree/kampo.pdf`, `contrib/issue-598-cmap-other-fonts.pdf`, `tests/corpus/many-boxes.pdf`. |
| `recursion-depth` | `analyze` raises `RecursionError` when Python would exceed its 1000-frame recursion limit, counting frames as if `LTPage.analyze` ran at frame depth 7 (`layout::ANALYZE_FRAME_DEPTH`, the depth under `extract_pages` and `pdf2txt.py`). `get_text()` of a deep group tree does not raise. | Python's limit applies to the whole stack, so the threshold depends on the caller; deep `get_text` recursion is only reachable from user code. | Pages whose text groups nest about 495 levels deep (long columns of text boxes with growing gaps): the exact depth where `RecursionError` starts differs by a few levels for callers with another stack depth. |
